# Контур — объекты и задачи

Мини-CRM для строительной команды: постановщик управляет объектами и задачами,
исполнитель видит только назначенные ему работы. Стек: React 19, TypeScript,
Vite, Supabase Auth и PostgreSQL.

## Локальный запуск

Требуется Node.js 22.22+.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item`. Адрес приложения:
[http://127.0.0.1:5175](http://127.0.0.1:5175). Без заполненных настроек работает
макет с вымышленными данными и переключателем ролей.

## Supabase

1. В отдельном Supabase-проекте выполните **содержимое**
   `supabase/migrations/202611060001_initial.sql` в SQL Editor.
2. Отключите открытую регистрацию и анонимный вход. В Auth вручную создайте
   подтверждённые аккаунты `manager@example.com`, `worker1@example.com`, `worker2@example.com`.
3. Выполните содержимое `supabase/seed.sql`: появятся профили, три объекта и шесть задач.
4. В `.env.local` задайте корневой `VITE_SUPABASE_URL` и публичный
   `VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...`, затем перезапустите Vite.

Пароли пользователей и серверные ключи не хранятся в исходниках. Правила доступа,
переходы статусов и запись истории проверяются базой, независимо от интерфейса.
Удаление объектов/задач реализовано архивированием с сохранением истории.

## Проверки и сборка

```bash
npm run check
bash tests/run-postgres.sh
npm run build:deploy -- 2b-test.duckdns.org
```

`check` выполняет TypeScript, тесты, форматирование и сборку. Проверка PostgreSQL
требует Docker в Linux/WSL и использует только временный контейнер. Пакет для VPS
создаётся в `deploy`; пустые настройки Supabase для него запрещены.

## Структура

- `src/App.tsx` — состояние приложения и операции с данными.
- `src/components/` — вход, общий диалог, редактор и карточка задачи.
- `src/TaskBoard.tsx` — очереди постановщика и личный список исполнителя.
- `src/demo.ts`, `src/presentation.ts` — локальные примеры и функции отображения.
- `src/AddressInput.tsx`, `src/addresses.ts` — подсказки адресов Москвы.
- `supabase/` — первоначальная миграция и тестовые данные.
- `tests/`, `.github/workflows/ci.yml` — автоматические проверки.
- `scripts/build-deploy.mjs`, `deploy/` — подготовка и установка сборки nginx.

[Подключение Supabase](docs/SUPABASE-SETUP.md) · [VPS: PuTTY/WinSCP](deploy/README.md) ·
[GitHub](docs/GITHUB.md) · [Объяснение для руководителя](docs/EXPLANATION.md) ·

Автоматические SQL-тесты воспроизводят роли и `auth.uid()` на отдельной PostgreSQL;
облачные входы, отключение регистрации и прямые запросы с реальными JWT проверяются
отдельно перед сдачей. Подсказки адресов проверяются в форме по OpenStreetMap,
не по официальному ФИАС. Большие объёмы, Realtime, загрузка файлов и восстановление
пароля в этот объём не включены. При подготовке использовался ИИ.
